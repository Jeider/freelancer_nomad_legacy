# rm0001: сценарий для озвучки

Разговор начинается сразу с приветствия вендора на ACU. Пробное вступление
с WFC и подходом Трента отменено после проверки в игре.

Мимика использует исходный `Autoplay → Character.facial(auto_lip=True)` из генератора
миссий, без анализа речи. Жесты также формирует `Autoplay` по существующей
`SEQUENCE_MALE_STAND_RHAND_ALT2`. В `SCRIPTS/RPG/rm0001/gestures/` сохраняются
8 полных шагов для каждого участника; тройка вход/conv/выход остаётся одним шагом.
Движок хранит позицию последовательности на протяжении разговора. Смена реплики
не привязывает жест к номеру фрагмента: выбор делает `rpg_gesture_rotation.h` в клиенте.
`CONV` разрешён только торговцу при длительности звука не менее 15 секунд.
Длительность берётся из `START_SOUND` выбранной RU/EN-сцены, без хвоста мимики.
Для Трента эти шаги всегда пропускаются: остаются `FSTHIPB` и `CROSS/UNCROSS`.
При пропуске шага сохраняется порядок исходной последовательности. Смена реплики
и пропуск её по Esc не прерывают жест. Завершившийся шаг останавливается; следующий
запускается при следующей реплике этого персонажа. Закрытие разговора освобождает
все дорожки. Постоянная сцена держит взаимный IK головы и глаз, а при показе
вариантов ответа камера переключается на игрока. Анимации общего персонажа
обновляет только постоянная сцена, один раз за кадр.

Вендор `rpg_biz_contact` носит `rh_commtrader_body` без военной фуражки;
команда `runtime` применяет этот костюм через DataFolder вместе с диалогом.

Источник: `story/rpg/rm0001.json`. 32 фрагмента на каждом языке, включая две
архивные реплики 0003/0011. Они сохранены для совместимости записей и не используются
в обновлённом разговоре. Новые 0022–0032 нужно озвучить на обоих языках.
0022/0023 объясняют лицензию и постоянный достигнутый допуск; 0024–0032 образуют
отдельную ветку обучения посадке, сцепке и сдаче состава.
Пока новые записи не готовы, `runtime` показывает эти реплики текстом.
После записи выполнить `install-audio`, `scenes`, затем `runtime`, чтобы
подключить новые голоса. Существующие файлы озвучки не нужно перезаписывать.
В тестовой версии все категории Трента открыты. Реальные ограничения по навыку
и сохранение лицензии запланированы отдельно в `docs/ru/re/train_courier_design.md`
репозитория движка.
Это разговор Трента с главой местного торгового управления о работе машинистом:
приветствие, вопрос о заданиях, предложение работы, выбор 2/5/10/20 вагонов,
выдача наряда, отказ по репутации, вопросы о требованиях и прощание.
Каждая произносимая реплика Трента имеет отдельный fragment ID.

Генерация и установка аудио ограничены явно выбранным RPG-диалогом.
THN собираются отдельной командой `scenes` после установки озвучки. Запись, резервирование и откат игровых DATA-файлов
выполняются исключительно через DataFolder. Сюжетные и космические
генераторы не получили автоматического переноса в игру.

## Подготовить тексты

Из корня Pythonlancer:

```powershell
.venv/Scripts/python.exe -B single.py rpg prepare
```

Таблицы `ru/lines.csv` и `en/lines.csv` находятся в
`results/rpg/rm0001/prepare/both/`. В таблице указаны роль, текст и стабильное
имя итогового WAV. Тексты редактируются в `story/rpg/rm0001.json`.
Номера существующих фрагментов не менять; новые добавлять с новым номером.

## Выбрать голос и собрать озвучку

Трент использует штатный класс `Trent`. Торговец имеет отдельный класс
`story/rpg/actors.py: RpgTradeDirector` с нейтральной подачей и скоростью 1.
Он назначен в поле `casting` каталога `rm0001`. Подмены голосом Хасслера нет.
Для клонирования нужны собственные образцы `RpgTradeDirector.wav`
в `Assets/VOICE_SOURCE_RU` и `Assets/VOICE_SOURCE_EN`, а также `Trent.wav`
для соответствующего языка. Поддерживаются и другие штатные форматы образцов.
Перед генерацией проверяются все образцы выбранных языков, чтобы не начинать
неполную запись. `--vendor-actor` остаётся явным разовым переопределением.

```powershell
# Проверка текстов, актёров и путей без обращения к голосовому сервису:
.venv/Scripts/python.exe -B single.py rpg voices --group rm0001 --language both --dry-run

# Генерация пользователем через настроенный голосовой backend:
.venv/Scripts/python.exe -B single.py rpg voices --group rm0001 --language ru
.venv/Scripts/python.exe -B single.py rpg voices --group rm0001 --language en
```

Используются штатные `VoiceLine`, `CutsceneSound`,
`AudioFolder.generate_cutscene_sounds` и настройка `VOICE_BACKEND`.
Все записи одной группы лежат вместе:

```text
Assets/AUDIO_CUTSCENE_RU/rm0001/rm0001_frag0001_l001_vendor.wav
Assets/AUDIO_CUTSCENE_EN/rm0001/rm0001_frag0001_l001_vendor.wav
Assets/AUDIO_CUTSCENE_RU/rm0001/rm0001_frag0004_l001_player.wav
```

Существующие MP3/WAV штатный генератор пропускает. После изменения текста
или голоса уберите вручную соответствующую старую запись для перегенерации.
План `voice_plan.json` сохраняется в `results/rpg/rm0001/voices/<language>/`.
Текст для backend проходит штатную обработку VoiceLine; в CSV/плане хранится
исходный текст сценария, включая возможные обозначения ударений.

VoiceStudio запрашивает WAV и сохраняет PCM16 WAV без MP3-кодирования.
Частота и число каналов сохраняются из ответа сервиса. Обрезка начальной
тишины также остаётся в PCM WAV. Существующие MP3/WAV автоматически
не конвертируются и не перезаписываются; их пропуск при повторном запуске
сохранён. Если нужен новый PCM-вариант старой записи, сначала уберите именно
её старый файл из папки генерации. Настройка Steos не менялась.
## Перенос только этого базового диалога в игру

```powershell
# Проверить готовые WAV и план переноса, ничего не меняя в игре:
.venv/Scripts/python.exe -B single.py rpg install-audio --group rm0001 --language en --dry-run

# Установить уже записанные фрагменты:
.venv/Scripts/python.exe -B single.py rpg install-audio --group rm0001 --language en

# Одна команда: записать выбранный диалог, затем установить его аудио:
.venv/Scripts/python.exe -B single.py rpg build --group rm0001 --language en
```

Для русского языка используйте `ru`, для обоих — `both`.
`voices` по-прежнему только записывает исходники; автоматическая установка
включена исключительно в отдельной команде `rpg build`. Она не запускает
сюжетные миссии, космические голоса или другие rm-группы.

Игровые пути:

```text
DATA/AUDIO/MOD/RPG/rm0001/*.wav
DATA/AUDIO/MOD_ENG/RPG/rm0001/*.wav
DATA/AUDIO/RPG/rm0001_sounds.ini
DATA/AUDIO/RPG/rm0001.json
```

WAV копируются без перекодирования. Проверяется каждая запись выбранного языка:
PCM16, ненулевая длина, полный набор семплов. Измеренная длительность и SHA-256
сохраняются в manifest для последующей сборки сцен. Отсутствующий/повреждённый
фрагмент отменяет весь перенос. Старые MP3 автоматически не конвертируются.
При установке одного языка уже установленный другой сохраняется.

Отдельный sound INI содержит `DX_<имя_реплики>_ru` и `_en`, без коллизий.
Именно эти nicknames использует генератор THN.
В рабочие `bin/freelancer.ini` и `bin/freelan_en_port.ini` однократно добавляется
только `sounds = audio\RPG\rm0001_sounds.ini` в секцию `[Data]`. Банки сюжетной
и космической озвучки не переписываются. EXE и DLLS/BIN не используются.
Обе языковые записи звука доступны независимо; локализованная сцена использует нужный
nickname по языку озвучки. Для подхвата новых регистраций перезапустите игру.

Отчёт — `results/rpg/rm0001/install-audio/<язык>/audio_install.json`
(для совмещённой команды — `build/<язык>`). Резервные копии изменяемых файлов
лежат рядом в `backups`; при ошибке записи выполняется откат.
`--game-root` позволяет проверить перенос на отдельном дереве с копиями
двух конфигураций `bin`, не меняя работающую игру.

Установка аудио ещё не включает проигрывание разговора: интеграция THN,
выборов, Esc, ротации и субтитров в клиенте остаётся отдельным этапом.

## Разделение обязанностей

* `story/rpg/rm0001.json` — тексты и проект ветвления разговора.
* `story/rpg/script.py` — проверяемая модель и адаптер к VoiceLine/CutsceneSound.
* `managers/rpg_voice.py` — подготовка/генерация через существующий backend.
* `managers/rpg_audio.py` — проверка и установка звука только выбранной группы.
* `story/rpg/scene.py` — одна реплика: штатные Autoplay, жесты и автоматическая мимика.
* `managers/rpg_scene.py` — сборка локализованных THN по установленным WAV.
* `files/rpg_audio.py` — формирование sound INI и точечной регистрации.
* `tools/data_folder.py` — единственная точка записи DATA, резервирования и отката.
* `files/rpg_recordings.py` — представление CSV и плана записи вне DATA.
* `tools/rpg_voices.py` — аргументы командной строки.
* `single.py rpg` — ранний вход без инициализации LancerCore и сюжетных миссий.

Другой набор выбирается через `--group rm0002` после создания
`story/rpg/rm0002.json`. `--output` меняет папку таблиц, отчётов и резервных копий;
сама эта папка должна быть вне DATA. Сценарий не регистрируется в StoryMission и не влияет
на сборку сюжетной кампании. Подключение к движку выполняется отдельной командой `runtime`.

## Собрать катсцены по готовой озвучке

```powershell
.venv/Scripts/python.exe -B single.py rpg scenes --group rm0001 --language en --dry-run
.venv/Scripts/python.exe -B single.py rpg scenes --group rm0001 --language en
```

Результат: `DATA/SCRIPTS/RPG/rm0001/en/rm0001_frag0001.thn` и остальные
фрагменты, `manifest.json` и отдельный `subtitles.xml` в той же папке.
Для русского языка используется `ru`; для обоих — `both`. Отсутствующая озвучка
или несовпадение SHA-256 отменяют сборку до записи файлов. Каждый язык измеряется
независимо. `scenes` не запускает TTS и не переустанавливает звук.

Один THN содержит одну реплику, одного привязанного персонажа, ссылку на камеру,
монитор и звук. Он не загружает интерьер, костюмы, свет, корабли, Blender dump
и не меняет положение игрока. События создаются библиотекой миссий 14+;
автоматическая мимика остаётся шаблонной, без распознавания фонем.

Контракт для будущей сессии движка записан в manifest: существующий NPC
связывается через Actor/Mirror (`BindMode=2`), Трент — через `Player`.
Сессия один раз ставит персонажей и создаёт камеры `RpgCamera_vendor` и
`RpgCamera_player` с ракурсами конкретной комнаты. THN ссылается на них через
`REFERENCE`; у DEFORMABLE этот флаг не используется. Сессия обязана проверять
наличие актёров/камер до запуска, чтобы исключить fallback создания персонажа.

Каталог сборки описывает только файлы (`runtime_connected=false`). Подключение
выполняется отдельно после установки клиента и Content.dll с поддержкой фрагментов:

```powershell
.venv/Scripts/python.exe -B single.py rpg runtime --group rm0001 --dry-run
.venv/Scripts/python.exe -B single.py rpg runtime --group rm0001
```

Команда создаёт `RPG/rm0001_dialog.ini`, `SCRIPTS/RPG/conversation.thn` и подключает
их к существующему `RPG/rh_biz_contact.ini`, убирая старый сюжетный click_script.
NPC/костюм/точка присутствия сохраняются. Сессия использует камеры ACU и PCU
реального места `mFloor2/01` бара Бисмарка; NPC берётся из Mirror нажатого контакта.
Существующие персонажи удерживаются до закрытия разговора. Esc обрывает текущий
звук/мимику, подтверждённый выбор применяется один раз после реплики Трента;
Esc в меню вагонов возвращает основное меню. Варианты приветствий/подтверждений/
отказов идут перемешанными без немедленного повтора, первое приветствие — 0001.

Язык THN выбирается по PortVoice. Пока RU-файлов нет, используется EN;
если нет THN или соответствующего WAV, остаётся текстовое представление. UI использует язык
интерфейса. Отдельный XML субтитров не сливается с общим сюжетным XML.
Порог репутации включается при заданном `rules.reputation.minimum` и повторном
`runtime`; при null проверка отключена. Для этого контакта фракция — rh_grp.
Проверка выполняется перед предложением и ещё раз перед выдачей наряда.
Сборка и тесты состояния не заменяют визуальную проверку ракурсов в игре.

При перезаписи голоса `runtime` допускает временно отсутствующие WAV и перечисляет
их в `runtime_install.json`, не восстанавливая старые записи. Уже существующие WAV
должны совпадать с хешами каталога сцен. После новой озвучки выполнить `install-audio`,
затем `scenes --language en`; команды не меняют привязку разговора.
